# длина по изометриям

Скрипт берёт pdf с изометриями и считает длину трубы на листе. Ветки тоже. До ПОДКЛЮЧЕНИЕ и СМ, кусок один раз.

ИИ смотрит картинку и говорит какие цифры это длина. Складывает python. Сомнительное не угадываю, в таблице review.

Свою модель на этих 10 листах не учил. Ниже написал как это делать, когда будет нормальная выборка.

## что где лежит

`data` — исходные pdf с изометриями, их программа читает.
`web` — сайт-окно: вёрстка, стили, кнопка «Рассчитать».
`output` — уже посчитанное: таблица, json, картинки разметки.
`output\llm_raw` — ответы модели по каждому листу, их можно править руками.
`output\markup` — лист с тем, что вошло в сумму.
`output\overlays` — лист с метками D1, D2, по ним проверять.
`.env` — ключи API, в git не кладётся. Образец: `.env.example`.

Код в корне: `app.py` открывает окно в браузере, `run.py` считает из консоли.

## длина

Беру участки по оси и ответвления.

Не беру вложенное (в примере 916 и 300 внутри 1950 и 840), общий габарит если уже есть куски, координаты X/Y/Z, DN, опоры, кружки позиций, штурвал.

Цифры из pdf, OCR не ставил.

Лист 7 LC_1040: 60+1950+650+840+522+250+34 = 4306, как в примере.

## как запустить

Нужен python 3.10+. Папка проекта `iso_length`. Pdf по умолчанию: `data\02_Изометрии_10_листов.pdf`.

Один раз ставишь окружение:

```
cd iso_length
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

Ключи в `.env`, без кавычек и без пробела после `=`:

- Groq (бесплатно): https://console.groq.com/keys → `GROQ_API_KEY=gsk_...`
- OpenAI / Codex (платно): https://platform.openai.com/api-keys → `OPENAI_API_KEY=sk-...`

`.env` в git не клади.

## как лучше учить модель, если дадут пачку листов

На 10 листах учить нечего. Эталон длины один (4306), а модели надо на каждый размер: брать / не брать / это габарит / это штурвал. Без такой разметки она выучит шум.

### что просить у заказчика

Не «ещё pdf», а пачку изометрий плюс кто-то, кто умеет читать длину. Лучше 200–300 листов разных линий, не десять копий одного узла. Если есть ведомость длин по линиям - ещё лучше, по ней ловить грубые промахи.

### как размечать дёшево

Тот же скрипт. Groq (или что будет) кидает черновик в `output\llm_raw`. Человек открывает `overlays`, правит json. Python считает сумму. Так копятся примеры: число, текст рядом, решение.

Учить надо не сумму листа, а решение по каждому D1, D2. Иначе снова сложит габарит и куски вместе.

Листы в обучение и в проверку резать целиком. Нельзя куски одного листа и туда и туда.

### что учить, по шагам

Цифры из pdf уже есть. С нуля зрение городить рано.

Сначала простой классификатор (даже без видеокарты): значение, что написано рядом (СМ, штурвал, опора, DN), есть ли рядом большее число куда это влезает, место на листе. На 150–300 размеченных листах этого хватит, чтобы габарит и штурвал отсекать лучше, чем 7B у себя на карте.

Зрение дообучать только когда json уже чистые. Иначе модель повторит чужие ошибки. На RTX 3070 8 ГБ нормально сидит маленькая VL, 32B не влезет. Локальная 7B изометрию читает слабо, на неё одну ставить не стоит.

Внешнюю модель типа Groq можно оставить на спорное: классификатор уверен - берём, нет - в review человеку.

### как понять что стало лучше

На проверочных листах: совпали ли include с человеком, сошлась ли сумма с ведомостью, отдельно - не пролез ли габарит в длину. Учебный 4306 оставить контрольным, в обучение его не мешать.

Пока выборки нет, рабочая схема такая же как сейчас: модель снаружи, сумма кодом, спорное руками.
